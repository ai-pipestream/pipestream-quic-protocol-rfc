Implemented scope
  SessionStore.reclaimOutput checks terminal work, verified child closure,
  external output expiry and dependent parent settlement. It uses the same
  paired-store, two-transaction release protocol as input reclamation. Exact
  reader/writer/callback-credit pins block before initial inspection/intent;
  an unborrowed reader credit has no funding identity. The first transaction
  verifies every promised published output before persisting eligibility.

  OutputStore visits the admitted slots, at most 256, and verifies all remaining
  names, admitted identity, producing fences, funded geometry and published
  descriptors. After checked release intent, missing names may represent an
  interrupted removal; remaining names are never exempt from validation.
  Staging aliases are removed and synchronized before installed names. Funding
  is removed and synchronized only after all output names disappear.

  Physical quota tracks prepaid funding, not individual output file sizes.
  Unlinking outputs does not refund that funding. Same-process interrupted
  funding removal retains the exact reserved charge until synchronization.
  Restart reconstructs physical funding, while logical completion still requires
  retained release evidence. Output release preserves input, manifests, receipts
  and immutable eligibility timestamps. No schema or wire grammar change.

  Existing child-closure verification remains a session-wide streaming audit;
  bounded slot visits do not establish constant-time cleanup or a measured
  whole-process memory/latency guarantee. Process-death tests are not power-loss
  tests. Instrumented boundary failures are not failing-fsync syscall evidence.
  Java durable endpoint/client integration, neutral two-direction failure/resource
  evidence, durable session retirement and the original external workload with
