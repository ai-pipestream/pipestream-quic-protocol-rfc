Authority::start_runtime owns the real execution pool and separate native
read-lease, retention and retirement maintenance threads. The execution pool
already has independent cancellation/deadline/closure reconciliation. Existing
durable jobs are discovered without a resubmission or volatile queue replay.
Stop and health inspection are nonblocking. Explicit shutdown joins and can
wait for application I/O; dropping requests stop and leaves live roots/pins
owned by running threads. Runtime completion does not assert that separate
connection metadata or input/output file jobs have finished.

Three actual-TLS/input-stream tests, with local control dispatch:
  runtime_discovers_admitted_work_and_retires_only_after_read_pins_and_safe_time
    Admit before starting runtime; execute the real copy callback; close the
    sealed root; pause destructive maintenance on CLOCK_UNSAFE; restore safe
    time; retain the session while a read is pinned; retire after releasing it;
    refuse old creation identity reuse. The read's 30-second idle/lifetime
    keeps this explicit-release test separate from automatic read expiry.
  runtime_expires_reads_and_requests_stop_while_a_callback_is_blocked
    Hold the only callback worker on a second job. Background maintenance
    closes a first job's read lease before another foreground check. Stop
    does not wait for the callback or falsely assert that it completed. After
    release, the accepted second job finishes normally; stop is not cancellation.
  runtime_rejects_invalid_limits_and_duplicate_execution_ownership
    Refuse out-of-range batch/interval values and a second execution owner.
    A new runtime can start after the first has stopped and joined.

Failure-classification unit test:
  maintenance_retries_only_explicit_clock_capacity_and_storage_contention
    CLOCK_UNSAFE, LIMIT_EXCEEDED and typed SQLite BUSY/LOCKED may retry.
    Corruption, arbitrary I/O and other protocol errors are fatal. No error
    strings or new production SQLite dependency are used in the transport.
    Fatal maintenance state must be supervised by the enclosing listener;
    this component does not itself stop execution on a maintenance fault.

Three execution regressions:
  executor_accepts_retained_durable_only_work_without_adding_result_delivery
    Before the fix, deployment support for results rejected a retained
    durable-only session with EXTENSION_UNSUPPORTED, "session profile
    combination changed". The test failed with exit 101. Execution now uses
    the retained profile combination without enabling unsupported profiles.
    Log: /tmp/pipestream-v2-runtime-profile-red.log
  worker_pool_stop_request_does_not_wait_for_a_discovery_state_lock
    Before the atomic stop signal, a deliberately held discovery lock kept
    request_stop blocked beyond 100 ms. Original handle 14088 exited 101.
    try_snapshot now reports a busy lock as None, not idle/healthy state.
    Log: /tmp/pipestream-v2-runtime-stop-red.log
  failed_worker_pool_startup_never_dispatches_an_application_callback
    A startup barrier prevents dispatch until every native thread exists.
    Deliberately bypassing the barrier made the test fail with exit 101:
    "callback ran before all pool threads existed". The barrier is restored.
    Injected thread creation failure leaves admitted work unexecuted; a
    subsequent successful pool starts that callback exactly once.
    Log: /tmp/pipestream-v2-runtime-startup-red.log
