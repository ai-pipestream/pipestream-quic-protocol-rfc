Contract and implementation
  Section 12.5 already requires sealed membership and admitted-or-terminal child
  obligations before completing authority expansion. The Rust completion path
  now checks that rule in the same transaction as the proposed transition.
  NOT_READY leaves production incomplete with the current attempt/local lease;
  it does not publish FAILED or incorrectly enter WAITING_CHILDREN. Committed
  declarations/admissions from the callback are not rolled back by this refusal.

  The same check audits jobs claiming completed expansion during integrity
  checking and reopen. Unresolved obligations become corrupt-storage refusals;
  unrelated SQL/storage/resource errors retain their original classification.
  The scan streams missing-job members and verifies their typed work records.
  Admission is distinct from execution: admitted children may be unfinished,
  and a legitimate terminal inputless child has no missing admission obligation.
  There is no wire, profile, schema or private storage-format revision.

Reviewed tests and fixtures

Limits and remaining work
  The coverage scan has bounded application memory but can visit the whole child
  scope; no new large-tree performance or whole-process resource measurement was
  made. SQL storage corruption outside this invariant remains subject to the
  existing broader integrity audits. No Java source, dependencies, or external
  examples changed, and their earlier evidence was not relabeled as fresh.
  This is local authority verification, not both-direction authenticated Java V2
  wire conformance. Full Java retry/cancellation/results/cleanup/retirement/
  transport/client behavior, the neutral cross-language failure driver and every
  original external workload/equivalent authenticated durable streaming-gRPC
  deliverable remain required. The full goal is active and incomplete.
