Scope and boundaries
- CoreServer is a reusable actual QUIC-v1/ALPN pipestream/2 listener, with the
  independent Java TLS guard, explicit caller mapping and HMAC Retry tokens.
  It implements Core only and never advertises or simulates durable profiles.
- One client bidi Stream 0; incremental deterministic control framing and
  negotiation; strict shared IDs from one; all 15 profile-dependent control
  families receive correlated EXTENSION_UNSUPPORTED. Post-detach valid requests
  receive NOT_READY, including later increasing detach requests. Malformed
  framing/direction/correlation remains fatal. Unknown ignorable bodies are
  consumed without buffering or changing request identity.
- Client FIN after detach preserves all preceding complete requests' replies.
  After local writes drain the server sends its FIN and leaves graceful parent
  close to the client. Netty native write acceptance is not a peer ACK. Absolute
  detach lifetime remains armed; timeout/reset/stop asserts no work completion.
- Live independent timers bound handshake, missing/partial/idle control,
  oldest queued write and absolute detach. Completed requests cannot renew an
  older blocked write or detach; partial bytes cannot renew the frame deadline.
- Global admitted connections include incomplete handshakes. Mapped owners
  and the shared anonymous/unmapped bucket have per-owner ceilings. Native
  close finishes before its admission permit is released; cleanup is idempotent.
- Excess connection handling uses one additional packet-local native transport,
  synchronously closed after the codec processes the Initial packet. No rejected
  handshake queue or asynchronous refusal pool exists. The peer sees QUIC
  transport CONNECTION_REFUSED (0x02), not a synthetic application response.
- Control write counts/bytes are bounded until native acceptance. Configuration
  caps connections*(queue bytes + maximum body + read chunk) at 128 MiB.
  Native TLS/retransmission/receive allocations and JVM/object overhead are
  separate. These counters/configuration gates are not measured total heap/RSS.
  Core has no object streams. Future durable objects require independently
  proven shared data/control credit, including batched credit replenishment.
