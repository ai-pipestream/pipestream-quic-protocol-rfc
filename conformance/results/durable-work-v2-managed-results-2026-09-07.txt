ResultStore reuses bounded immutable payload storage with a purpose-qualified,
trusted authority/owner binding and immutable quotas. ManagedResults integrates
the durable client's saved selection and authenticated stream with owned file
workers. Full-length reservation precedes reception; installation follows verified
FIN, hash/length checks and file/directory synchronization. Local reads require
the exact saved selection and verify bytes again at EOF. No automatic eviction,
replacement work, cross-owner lookup, new dependency or wire/journal-format change.

Section 12.7 now requires clients to distinguish local copies from newly authorized
transfers: local possession does not grant remote access, renew availability, or
mean expiry/revocation can recall bytes already delivered. No remote-erasure claim.

The language pairs remain V1 evidence, not independent Java V2 interoperability.

The managed path is a library, not yet the default CLI output path. Existing
arbitrary-path downloads/exports still require trusted stable directories and
can leave temporary files after process death. The managed store never scans
or deletes those unrelated files. Repeated managed downloads are separate
charged copies. Owner counts, file lengths and chunk ceilings are structural
bounds, not measured total heap/RSS or filesystem-block reservations.

The original full goal remains active: managed-store CLI/export integration,
complete independent Java V2, neutral cross-language failure/resource driver,
and external chunk/distribute/transform/reassemble workload plus equivalent
authenticated, durable streaming-gRPC baseline with pinned raw measurements.
No main merge, deployment or Internet-Draft submission.
