Scope and limits
  Java authority format 3 preallocates scope, work, first-fence and shared-clock
  images. Each checked header binds the role, slot, immutable owner-qualified
  identity, revision, used/capacity lengths, body checksum and remaining rewrite
  credits. Scope creation reserves four image writes; a declared member reserves
  two work-image writes and one fence-image write. Each credit also funds one
  shared-clock write. Ordinary writes preserve all retained reservations.

  Recovery checks full images, exact ownership links, clock encoding, geometry
  and retained credit. Growth preserves body/revision and requires ordinary
  headroom. Earlier experimental formats are refused, not converted. The native
  bounded VFS and BLOB primitive are unchanged; this is independent Java V2
  state, not reuse of Rust or V1 job states. No wire encoding changed.

  These are guarded file-length and transaction guarantees. They do not prove
  allocated disk blocks, RSS, throughput, disk-device durability or complete job
  admission. Helpers require the caller's owned writer transaction and rollback
  on failure. Java's endpoint still advertises Core only. Full Java durable
  execution/results/retirement, cross-language V2 failure-driver evidence and
  the external workload with equivalent durable streaming-gRPC remain required.
