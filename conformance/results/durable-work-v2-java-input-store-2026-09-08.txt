Scope and limits
  Independent Java InputStore receives immutable input payloads using Java file
  channels, typed V2 headers and the V2 incremental object verifier. It reserves
  two complete file lengths and two names before reception, verifies exact
  length/hash/FIN, forces the file, installs by exclusive hard link and syncs
  object and staging directories before returning and refunding staging space.
  Duplicate installation verifies existing bytes without overwriting them.

  The private policy and object envelopes retain an installation identity,
  limits, owner-qualified context, exact header and checksums. Recovery validates
  the whole layout and installed bodies before removing abandoned staging names.
  Installed objects remain charged; this unit does not reclaim them. One process
  owns the store, and readers/receivers share a bounded active-handle count.

  Lookup now completes file force and directory synchronization even when the
  object is already readable. Mere visibility following an interrupted force
  does not prove durable installation. Readers verify the same descriptor with
  an 8 KiB buffer before exposing payload-only bytes.

  This is not authentication, work admission, operation replay or a job. Explicit
  authority-store binding and atomic input/job/receipt/output/metadata funding
  remain required. Java's endpoint still advertises Core only. No wire encoding
  changed. Full Java execution/results/retirement, the neutral cross-language V2
  failure driver and the original equivalent streaming-gRPC workload remain open.

  File-length/name bounds are not filesystem-block preallocation or a promise
  against device failure. Local POSIX permissions, hard links, cooperative locks
  and file/directory sync are required. These tests ran as an unprivileged user;
  the read-only-file durability regression requires enforced owner permissions.
  Process interruption is not a power-loss test. The streaming resource case uses
  synthetic monotonic progress for the file pipeline; separate tests drive idle
  and absolute expiry. It is not a transport latency/throughput benchmark.
