Implementation scope
  DurableRequests owns one connection's decode-order correlation, immutable
  binding, input/result pending counts and drain exclusion. Independent ticket
  copies retain capacity for real worker/response/transfer ownership; only the
  final close releases it. Closing the connection does not erase those owners.
  Detach waits for other accepted owners without asserting work completion.
  Completed-session requests exclude competing requests/transfers until every
  owner of the completed response has released its ticket.
  SessionStore.completed authorizes the attached session, compares generation
  and exact root summary, verifies retained closure, and bounds the response.
  It does not expire outputs or itself prove that a connection drained.
  Messages.Complete now accepts a structurally valid child-scope summary for
  authorized CONFLICT refusal, matching Section 12 and the existing CDDL.
  Such a request previously failed as FRAME_ERROR before authority dispatch.

Evidence boundaries
  These are storage/connection-library tests with real SQLite state, not a
  Java durable listener or proof of actual QUIC response/FIN delivery. The host
  must retain tickets through its real bounded workers, stream jobs and write
  completions; it must enforce connection deadlines and native credit bounds.
  Limits here are per connection; whole-authority worker quotas and whole-process
  RSS are separate. An application write completion does not assert peer ACK.
  Full Java durable server/client integration, the neutral two-direction
  failure/resource driver and equivalent external workload/gRPC comparison
  remain mandatory. No new durable profile is advertised by this checkpoint.
