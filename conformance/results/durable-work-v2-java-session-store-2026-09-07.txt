  This is exact-integer/exhaustion evidence, not retirement implementation.

  Other-owner denial precedes receipt decoding, including corrupt storage.
processDeathBeforeAndAfterCommitPreservesAtomicRecovery
  Owned child JVMs halt without Java/SQLite destructors: exact exit 23 before
  COMMIT, 24 after it. Recovery proves absence before and replay after commit.
  This is real process/storage recovery, not a network ACK-loss scenario or
  exhaustive storage-device/power-loss simulation. Timed-out children fail
  the test and are explicitly terminated; a timeout never counts as a refusal.

  64 KiB main database, 1 MiB WAL, 64 KiB journal/shared-memory caps.
  Actual SQL capacity failure is LIMIT_EXCEEDED with SQLException cause.
  Prior replay/attachment and reopen remain possible, allocators do not
  advance for the refused creation, main file length stays <= 65,536 bytes.
  These are file-length/logical-state assertions, not allocated blocks/RSS.
