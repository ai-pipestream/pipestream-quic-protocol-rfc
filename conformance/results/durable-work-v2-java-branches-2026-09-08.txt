Implemented contract
  Mode 1 callbacks page their own direct child scope, resolve committed child
  outputs and stream actual bytes into parent processing. A claim requires real
  successful STRICT child closure, not membership sealing alone. The scheduler
  observes child-summary readiness without occupying a worker; the committing
  claim still verifies all closure evidence. This prevents an unresolved parent
  at the front of a one-worker page from repeatedly displacing its own children.

  Callback I/O checks current parent owner/application permission, attempt,
  local lease, deadline and exclusion fences. The metadata snapshot and physical
  open share the paired-store monitor with replacement claims. Child descriptor
  identity is not bearer authorization and no result locator is dereferenced.
  External result expiry does not end the accepted parent's internal dependency.
  Actual child file identity, length, digest and content type must match the
  successful manifest. Storage errors preserve the recoverable parent rather
  than manufacturing a computation outcome, even if the callback catches them.

  Each callback reserves one own-input handle, one sequential child-reader
  credit for a branch and one writer credit for a nonzero output count. A fresh
  admission whose policy cannot supply that intrinsic geometry refuses before
  output funding or a receipt. Transient occupancy is checked at dispatch.
  A borrowed reader adds a per-funding physical pin without another global
  handle charge. Credits are store-bound, single-borrow and cannot be released
  before physical closure. Every opened child reader must reach observed EOF
  and finish before successful return; a zero-length read cannot establish EOF.

  Child pages contain at most 256 identities and payload reads use the configured
  chunk ceiling. Metadata reads still perform session-wide closure verification,
  and both file lookup and opening hash actual payloads with fixed buffers.
  These are bounded-memory paths, not constant-time, zero-copy, throughput or
  total-process memory claims. Retained output allowances are not refunded by
  parent settlement; dependency-aware expiry/cleanup remains separate work.
  No wire schema, local storage format or public profile advertisement changed.

Review corrections
  Negative callback assertions can be caught by ExecutionRuntime and become a
  generic FAILED outcome. The new tests require exact terminal diagnostic codes
  outside callbacks; the swallowed-refusal test also proves the callback caught
  the expected refusal and continued to return success. Tests use real child
  publication/closure and physical output bytes, not synthetic terminal rows.
  Scheduler coverage places the parent and both children in the same page with
  one physical worker; page size one would avoid the starvation condition.
  A known closed child losing its job or output-liveness accounting is now an
  SQL storage error, not NOT_READY/OUTPUT_UNAVAILABLE turned into parent FAILED.
  The negative accounting fixture changes a genuinely settled job's checksummed
  image; its actual success manifest and child closure are not fabricated.
