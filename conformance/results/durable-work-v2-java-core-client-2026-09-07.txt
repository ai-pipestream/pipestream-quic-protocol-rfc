Behavior
--------
CoreClient binds one owned socket/event loop, verifies TLS and server capability
selection, and opens only client bidirectional Stream 0. Core alone is offered;
no data streams are permitted or durable profiles advertised. One monotonic
request identifies detach. Repeated public calls share a cached minimal stage
and cannot enqueue additional operations; derived-future cancellation does not
change transport state. Refused, malformed or incomplete drain is never success.

The client sends control FIN after locally draining the request. It requires a
correlated Detached and actual peer FIN before completing detach, then closes
with application error zero. Native write/FIN acceptance is not treated as a peer
ACK or durable outcome. Separate scheduled checks bound handshake, complete-frame/
idle-control, oldest local write and absolute detach lifetime, including callbacks
at the deadline. Partial data cannot renew frame time; complete ignored frames
cannot renew detach. TLS failures defer cleanup past the native alert callback.

Configured application queue/frame/read-buffer allowances are capped at 128 MiB
across at most 64 class-owned clients, including incomplete handshakes. Slots
remain charged through event-loop termination. These are admission policies,
not heap, total RSS, native handshake or retransmission memory measurements.
CoreOptions listener connection/per-owner limits do not configure this client.
Callbacks must use asynchronous continuations for blocking application work.

The independent malicious peer uses public binary codecs and actual QUIC/TLS,
not client internals. Script failures are inspected after fixture shutdown.
Early cancellation is gated before capabilities; the peer observes precisely
Detach(1) and actual client FIN before supplying its acknowledgment/FIN.
STOP is sent while the client send direction is unfinished, not after FIN.
Negative tests require the specific named failure, never observation timeout.
A 12000-byte ignored body crosses a 128-byte receive window. An ACK plus repeated
ignored frames without FIN fails within three seconds under a one-second detach
lifetime and five-second control timeout; at least three sends are observed.
The count test fills 64 silent-peer clients and checks refusal/replacement. A
separate 17 MiB-plus configured per-client allowance reaches aggregate byte
admission before the count ceiling. Neither test allocates or measures that full
allowance as live heap/native memory.

The tagged interoperability case launches the existing release Rust V2 authority
CLI with fresh explicit state, CA, server identity and principal mapping. Java
negotiates Core and detaches first anonymously, then with mapped caller identity.
Both client instances terminate; SIGTERM of the owned Rust test process must
exit zero with DRAINED. No running external service is stopped or modified.
This covers Java-client/Rust-authority Core only, not the reverse direction or
Java durable-work/results behavior. It is not the complete neutral failure driver.
