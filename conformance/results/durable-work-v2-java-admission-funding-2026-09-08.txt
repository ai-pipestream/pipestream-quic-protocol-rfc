Scope
  Java database format 5 and input policy format 3 implement internal funded
  admission on the immutable paired stores. Earlier private formats refuse;
  there is no conversion or wire-format change. The transaction checks owned
  attachment, explicit application/restart policy, declared membership, producer,
  cancellation ancestry, trusted UTC, representation limits and live capacity.
  Exact installed input is required; missing complete input is NOT_READY.

  Durable output allowances precede the atomic database commit of attempt 1,
  work, optional child scope, restartable job, replay receipt, representation
  requirements and clock watermark. Failed metadata commitment leaves charged
  file-store orphans, not an accepted operation. Exact replay does not refresh
  deadlines, re-read payloads or consume another admission allowance. Changed
  headers and declaration/admission operation-ID collisions are CONFLICT.

  The final application-authorization callback precedes the final trusted UTC
  sample. Recovery checks job/member/receipt coverage, parent/child identities,
  configured application and profile, limits, fixed-record credits, allocator,
  retention arithmetic and watermark against retained admission timestamps.
  Paired-store verification checks retained jobs' input and funding references.
  Scans decode bounded records and bounded owner strings, not a whole job map.
  They scan retained state and do not establish constant-time admission.

  Mode 1 starts WAITING_CHILDREN; mode 2 starts ACTIVE with an independent
  unfinished-expansion obligation. Caller children retain their own execution
  deadlines. Parent deadline/FAILED alone is not subtree cancellation. Section
  12 now explicitly distinguishes caller obligations from the local producer's
  parent-attempt/lease/deadline fence. Cancellation fences still apply.

  Work capacity is at least max(4096, 2048 + 1280*maximum_output_count), including
  329728 bytes for 256 outputs, with at least four remaining image credits.
  Each 2048-byte job reserves six writes; a new child scope reserves four.
  These are image/shared-clock reservations, not arbitrary SQL/device promises.
  Output funding retains r + 2*b + 2*n*8236 bytes and 1 + 2*n names, where r is
  the bounded funding record length, b the total output budget and n the count.
  Installation additionally needs one temporary r-byte record and one name.
  Ordinary input reception cannot consume these allowances after restart.

  Java's shipped endpoint remains Core only. This checkpoint does not implement
  worker acquisition/renewal/settlement, producer-1 ingress, actual output
  publication/delivery, funding consumption, orphan reclamation or retirement.
  It does not complete the V2 failure driver, full cross-language/resource gates
  or the original external workload and equivalent streaming-gRPC comparison.
