Scope and boundaries
  The independent Java authority now commits local worker claims, renewals,
  expired-lease replacements, retryable failures and terminal failures. Internal
  lease numbers increase on acquisition, not on renewal. Replacement preserves
  the original wire attempt, input, child allocation, admission time and deadline.
  A live lease prevents replacement; stale or expired workers cannot renew or
  publish. Final owner/application checks precede the final UTC sample, which
  checks the pre-transition lease rather than a newly proposed renewal.

  ExecutionStore.Access is a retained execution-policy gate, not the presenting
  TLS certificate. SessionStore.expireExecution is owner-independent local
  maintenance: it needs no caller connection or former execution grant. A new
  failure requires trusted UTC at or after the original deadline. Existing
  cancellation/revocation fences retain precedence; parent failure alone does
  not cancel caller descendants. Already terminal maintenance observations
  issue no new time promise and may be read with an unsafe clock.

  Claims verify the exact paired input and output-funding files before committing
  ownership. Ordinary claim/renewal writes preserve settlement credits. A failure
  consumes one WORK and one JOB image credit. Deadline failure after a retryable
  failure consumes a second pair; recovery accepts that actual path while keeping
  four job cleanup writes funded. Terminal failure releases logical executor
  capacity, never the retained input/output bytes or a physical callback pin.
  A final UTC sample reaching a newly proposed terminal receipt's expiry refuses
  CLOCK_UNSAFE and rolls back, rather than publishing already expired evidence.

  ClosureStore verifies retained closure before parent execution and at recovery.
  Descending scope-ID traversal checks actual parent allocations, exact seals,
  ordered terminal members, counts/status roots, descendant closure, STRICT
  success, profiles and timestamp ordering. One invocation visits the session's
  scopes and members of summarized scopes with indexed lookups and bounded
  records; it retains at most 63 status hashes, not a recursive subtree map.
  Repeated calls repeat that scan. This is not constant-time scheduling, a
  measured large-session throughput result or a whole-process RSS claim.

  No wire grammar or dependency changed. Private database format 5 is unchanged;
  recovery now recognizes these implemented job transitions in its existing
  typed images. Java still advertises Core only. This checkpoint implements no
  callback scheduler, explicit wire-attempt retry, local producer-1 ingress,
  successful output writer/publication, closure writer, subtree cancellation,
  result read pins or retirement. Test-installed closure summaries are fixtures,
  not evidence of an implemented closure writer. The full cross-language V2
  failure driver and original external workload/equivalent streaming-gRPC
  comparison remain required; this checkpoint does not complete the goal.
