Scope
- TlsAuthentication configures actual QUIC TLS 1.3, ALPN pipestream/2 and no
  application early data. Server trust is explicit. Client service DNS/IP identity
  is checked inside the chain-verification callback using the existing independent
  Java SAN matcher, now also callable with a certificate. No Common Name fallback.
- Optional client-certificate authentication permits anonymous Core, not anonymous
  durable activation. A presented invalid certificate fails TLS. Missing/unmapped
  identity excludes optional durable/results; requiring either fails UNAUTHORIZED
  before any capabilities response. Capability records remain caller-supplied
  descriptions of implemented profiles, not proof that an endpoint implements them.
- Mapping hashes the complete verified DER leaf. Same-key certificate reissuance
  has a different key in that map. Atomic configuration replacement cannot change
  an existing connection's bound owner. Every durable caller check uses current
  mapping and credential time, including equality with certificate expiry.
- Netty fires channel-active before handshake-complete. The per-connection guard
  delays downstream activation until credential verification. Its read-only ready
  promise fails on TLS error, close or unregistration even if never activated.
  Stream dispatchers must require the guard before processing any request.
- Built-in Java clients have a zero-sized pinned Netty session cache. External
  caching clients can resume against this server: the guard rechecks retained
  chain trust/time and maps the leaf before application activation. Failed
  resumed credential verification sends a transport CRYPTO_ERROR, not an
  application refusal. Section 12 now makes this no-processing-before-revalidation
  requirement explicit. These credential checks do not replace durable session
  authorization, revocation, publication fencing or the accepted job's grant.
- Configuration bounds: 1 MiB of trust PEM, 256 anchors, 16384 mapped credentials.
  Peer verification bounds: 16 certificates and 64 KiB encoded chain after native
  parsing. These are not native handshake-allocation, total heap/RSS, listener
  admission or application-stream resource bounds. No application payload is
  buffered by this guard. Complete endpoint quotas/timers remain to be implemented.

Tests and regression trail
  V2TlsTest: nine substantive scenarios using actual loopback Netty QUIC and
  temporary EC certificates. The typed-capabilities dispatcher is a test fixture,
  not a claimed V2 durable reference endpoint.
  - Mutual TLS and two-certificate same-owner rotation; same-public-key reissuance
    remains unmapped unless the complete new DER leaf is configured.
  - Missing/unmapped Core, optional downgrade and required caller-dependent
    profile denial before response, including result-only required sets.
  - Untrusted/invalid-EKU/expired/future clients and inconsistent local cert/key
    material. The wrong-key test exercises local TLS key consistency, not a custom
    on-wire forged CertificateVerify implementation.
  - Exact DNS, literal IP and one-label wildcard; wrong name, multi-label wildcard,
    malformed references, CN-only, invalid server EKU and untrusted server chain.
  - Live expiry at equality and removed/remapped owner; no silent owner switch.
  - Actual resumed external clients, removed mapping and expired resumed credential;
    three reconnects with the built-in client prove full handshakes instead.
  - ALPN mismatch, never-ready guards, incomplete key configuration, empty/large
    trust files, excessive anchor/mapping counts and invalid owner labels.
  Test-only inspection of the pinned engine's isSessionReused flag observes the
  actual engine retained by the test provider, including after native cleanup.
  There is no production reflection or substituted TLS session. A timeout does
  not satisfy a negative readiness assertion; it requires exceptional completion.
