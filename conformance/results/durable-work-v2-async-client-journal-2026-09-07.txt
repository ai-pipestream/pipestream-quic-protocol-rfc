Scope
  pipestream_quic::v2_client::journal::Journal exposes async access to the whole
  core journal API: creation/binding, immutable intent/receipt, unresolved pages,
  work/manifest/reference evidence, scope membership/coverage and root-cut request.
  One dedicated worker owns journal initialization/open/audit, every database
  operation and final store/file-owner destruction. No user callback can be
  submitted through its public API. It does not perform TLS or correlate network
  replies; caller-supplied records still require authenticated transport evidence.

  Mutation::validate now shares the existing typed parameter rules without
  allocating a commitment or inventing a session identity. The core intent
  request/header helpers validate before cloning parameters; the async owner
  validates variable-size inputs before enqueueing them. Wire schemas, CDDL,
  frozen bytes, local client format 3, authority format and dependencies are unchanged.

  Options::in_flight is 1..=32, default 16. Queued calls, executing calls and
  completed replies not consumed or discarded all retain the same slot. Overload
  returns LIMIT_EXCEEDED; no unbounded waiter queue is created. Cancelling an
  accepted future abandons its reply, not the operation; its queued/running
  commit continues with its slot held. Returning a value transfers it to the
  application, rather than accumulating an internal completed-result history.
  A process-wide permit ceiling bounds 64 concurrent journal workers, including
  workers opening/closing storage. These are count/typed-record bounds, not an
  independently measured heap/native-memory/RSS or end-to-end latency guarantee.

  Clones share a short enqueue/close gate. close refuses new calls atomically;
  closed waits until accepted operations and final store/lease cleanup finish.
  shutdown performs both. A timeout around that wait does not complete cleanup.
  Last-handle drop closes acceptance and lets accepted jobs drain. A worker panic
  reports INTERNAL_ERROR; no retry, deletion or reset is inferred. Failed open
  waits for the worker to release its owners before reporting failure, avoiding
  a cleanup race for immediate reopen. No local shutdown acknowledges network
  DRAIN or cancels work at an authority.

  Unix ownership is an advisory lock on a stable empty <journal>.client-lock
  sidecar. A second cooperating async opener, including another process, refuses
  CONFLICT while the first worker owns it. Symlink/nonempty lock files refuse
  without overwrite. The private directory must not be modified by hostile
  actors; do not unlink the sidecar or bypass it with concurrent raw core-store
  access. The sidecar is not identity evidence or a way to repair missing history.

Nine substantive worker tests and one subprocess entry point
  persistent_intent_and_empty_root_coverage_round_trip_on_owned_worker
  cancelled_waiters_keep_running_and_queued_commits_charged_until_shutdown
  completed_but_unconsumed_replies_keep_their_capacity
  close_is_shared_but_dropping_one_handle_does_not_stop_others
  last_handle_drop_drains_accepted_commit_before_releasing_file_ownership
  panic_stops_the_owner_without_erasing_a_finished_commit
  invalid_arguments_and_options_refuse_without_queued_inventory_or_history_reset
  ownership_sidecar_refuses_symlinks_and_foreign_data_without_overwriting
  live_process_owns_the_journal_and_forced_exit_preserves_its_commit
  journal_worker_kill_child (subprocess entry point, no standalone scenario)

  Worker barriers are explicit fault/scheduling injection, not a simulated
  database. The tests run a current-thread Tokio runtime while a real worker job
  is blocked: both running and queued waiters are cancelled, their slots remain
  charged and excess calls refuse. Releasing the worker commits both original
  intents; shutdown/reopen verifies them and their unresolved receipt state.
  FIFO sequencing proves an unconsumed completed reply still holds its slot.
  No assumed sleep or scheduler timing determines whether those jobs are pending.

  The process test observes a flushed post-commit marker from its child, confirms
  that child is still live, observes a second opener's ownership conflict, kills
  the child and observes unsuccessful exit. Reopen retains the original intent
  without a receipt, rather than manufacturing completion or replacing identity.
  The panic test similarly verifies a real commit survives an injected later fault.

Isolated owner-capacity gate
  quinn/tests/v2_journal_resources.rs runs in a separate test process to avoid
  unrelated unit-test journals sharing its global ceiling. It initializes 64
  actual async journal owners, rejects the next one with LIMIT_EXCEEDED and checks
  that neither its database nor its lock file was created. After close/closed on
  all 64, a new journal is admitted while the old closed handles remain held.

  The reported bytes are the sum of the 64 empty main database lengths. They are
  not allocated filesystem blocks, journal sidecar sizes, RAM, RSS, or a workload
  performance result. No syscall-count claim is derived from the absent files.
