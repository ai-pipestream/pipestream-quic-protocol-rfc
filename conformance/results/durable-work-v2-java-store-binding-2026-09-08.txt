Scope
  Java database format 4 retains an installation UUID, exact local configuration
  and nullable input-store UUID under a bounded checksum. Every transaction
  verifies that record against the handle's immutable database identity.
  Input policy format 2 names its intended database UUID at initialization.
  SessionStore.bindInputs atomically records that root UUID in the database,
  preserving existing fixed-record completion-write reservations. A matching
  replay succeeds; another empty root cannot replace an already bound root.

  Setup holds the input owner's monitor through the writer transaction,
  verifies its live immutable policy, completes file/directory synchronization
  and commits the reverse binding. verifyInputs requires the already committed
  exact pair and never adopts an unbound database. Standalone input roots,
  wrong database identities and closed handles refuse before database access.
  There is no rebind, conversion or automatic identity reset.

  No wire format changed. This is neither authentication nor admission, and
  creates no protocol operation, session, member, input object or job. Future
  admission must check the pair again inside its committing writer transaction
  and atomically fund the full job/receipt/output/metadata write set. Java's
  endpoint remains Core only. Full Java execution/results/retirement, neutral
  cross-language V2 failures and the original equivalent workload/gRPC baseline
  remain required. Installation UUIDs do not prove backup freshness or defeat
  an operator able to replace both stores and their checksums.

Actual recovery and corruption oracles
  Owned child processes retain the open input owner and use Runtime.halt:
    exit 41: database and input root initialized; binding not committed.
    exit 42: bindInputs has returned after its database commit.
  After reopen, exit 41 must produce SQLException from verifyInputs until
  bindInputs completes explicitly. Exit 42 must verify immediately. Both then
  replay bindInputs, verify matching identities and require zero protocol rows
  and zero input-file/handle usage. Child waits and forced cleanup are bounded;
  no live cluster process is stopped. These are process crashes at completed
  I/O boundaries, not storage-device power-loss measurements.

  Real SQL mutation replaces ps_v2_meta.input_id with another nonzero 16-byte
  value without updating identity_hash. Current verification and SessionStore
  recovery must both refuse SQLException, while original payload bytes remain
  available from the independently held input store.
  A changed policy.cbor checksum must cause IOException on both current pair
  verification and input-root recovery. Neither corruption case deletes or
  silently resets retained data.
