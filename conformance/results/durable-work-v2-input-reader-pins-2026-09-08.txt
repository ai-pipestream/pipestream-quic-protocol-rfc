Java V2 per-object input reader pins, 2026-09-08

Scope
  InputStore counts acquiring and open readers by the exact immutable input
  path derived from installation/authority/owner/generation/full input header.
  Entries share the existing global handle bound; unrelated objects and receive
  credits do not appear read-pinned. Multiple readers and EOF retain pins until
  physical descriptor closure. Close releases once, including when close reports
  an error after the channel is already closed. An unresolved descriptor remains
  charged. Closing readers does not refund durable payload bytes or file names.

  inputPinned is a physical-liveness observation, not deletion authority. The
  collector must hold the store monitor through its physical action and prove
  durable eligibility separately. No payload deletion or retirement is enabled.

Static review
  Six tests exercise real files: multiple readers/two objects; exact shared handle
  exhaustion; missing and corrupt opens without phantom reader capacity; isolated
  authority, owner, generation, operation and application identities; real receiver
  and ReceiverCredit versus zero-byte EOF pinning; and close/reopen accounting.
  Review corrected an identity case that changed operation and work together and
  required an actual ReceiverCredit case in addition to the Receiver case.
  Exceptional OS close behavior is handled by production but was not injected by
  these tests. These tests do not establish a collector or process-death recovery.
