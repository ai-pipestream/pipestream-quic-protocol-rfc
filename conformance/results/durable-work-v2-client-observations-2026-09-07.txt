Scope
  The blocking client Journal now commits revisioned work views and full result
  manifests; remember_reference additionally commits the selected output index.
  Reopened references construct attachment and read requests from retained
  issuer/owner/generation/attempt/digest. Trusted endpoints and owner credentials
  remain separate configuration. Locator text is not an authentication source.
  Output availability remains the authority's fresh read decision; a manifest
  may remain useful evidence after bytes expire. Nothing here retries execution.

  Known admission, retry and cancellation/skip receipts constrain views/manifests
  regardless of reply arrival order. Changed terminal outcomes, fenced attempts,
  input/deadline/child commitments, output budgets and retained policy intervals
  are refused. Compatible stale replies return the newest stored view. Typed
  receipts are also compared with each other; receipt commit order is not assumed
  to be authority commit order. Scope-wide membership/ancestry coverage remains
  a separate, unfinished client component.

  Normalized operation target indexes select typed checksummed CBOR records.
  Default count ceilings are 4096 operations and independently 4096 work views,
  manifests and selected references. Each ceiling supports 1 through 1,000,000;
  inventory is never automatically evicted. Individual images are bounded before
  storage reads/decoding. Existing guarded SQLite file-length caps still apply.
  Inventory scans and receipt comparisons are blocking; record limits do not
  imply a measured latency, heap, native-memory or RSS bound.

  Local client format is 2. Format-1 journals refuse without conversion, deletion
  or replacing unresolved history. Authority format, wire/CDDL, dependencies and
  processing contracts did not change. Caller-supplied records still need actual
  transport authentication/correlation and output streams need byte/FIN validation.
  Checksums detect corruption; they do not authenticate hostile local edits.

  SQLite failing-insert triggers prove rollback of view/manifest/selection. The
  forced-exit scenario waits for a child process's post-commit marker, kills it,
  observes unsuccessful exit and exclusively reopens its view/manifest/selection.
  A greater-than-64-KiB manifest hits real 64-KiB database/WAL caps without partial
  installation or loss of earlier evidence; physical lengths and reopen are checked.
  These are actual storage tests, not whole-process workload resource measurements.
