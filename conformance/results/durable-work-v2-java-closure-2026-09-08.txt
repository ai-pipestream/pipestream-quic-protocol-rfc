Implemented contract
  Section 12.8 requires exact sealed membership, all terminal members and closed
  descendants before scope closure. A non-success child prevents STRICT parent
  success and settles an unresolved parent FAILED, except for an earlier terminal
  outcome or accepted cancellation/skip fence. This increment implements that
  writer in the Java authority library without changing wire or storage format.

  Descending generation/scope discovery selects one scope per step. A volatile
  cursor folds at most 256 ordered direct members plus one continuation key.
  Full membership and terminal status commitments are separate. No partial
  summary or encoded partial hash state is persisted. Recovery refolds retained
  immutable evidence, and another authority installation cannot use the cursor.
  Status-tree payload is bounded by 63 SHA-256 hashes (2016 bytes), excluding
  fixed object, hasher and cursor overhead. Existing descendant-summary audits
  still scan session evidence, at most once per direct-member batch using child
  evidence; the direct-page bound is not a total-work or transaction-time bound.
  Funded image writes retain the installation-wide reservation-header scans.

  A new summary consumes one prepaid scope-image write. Required STRICT parent
  failure consumes one prepaid parent work/job image pair in the same SQLite
  transaction. One shared clock write records final safe UTC. Root receipt
  retention overflow and a final clock jump overtaking a promised interval
  refuse and roll back the images together. No payload allowance is refunded.
  Existing summaries and terminal parent outcomes remain immutable. Lost return
  values do not authorize spending another completion credit.

  The scheduler runs closure maintenance separately from leaf callbacks and
  their owner grants. Local scopeSummary authorization precedes retained-state
  inspection; the caller must supply the exact complete seal. This snapshot API
  is not the wire checkpoint wait or completed-session DRAIN implementation.

  using an unchecked job record. Transaction error handling accepts Throwable

  commit; an AFTER_COMMIT observation failure never claims rollback.
