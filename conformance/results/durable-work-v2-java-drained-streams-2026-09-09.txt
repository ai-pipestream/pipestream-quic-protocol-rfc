Defect
------
quiche drains a stream after a local stream_shutdown(Read): incoming data is
discarded and the stream is removed from the readable set, so no later
stream_recv() can touch it. When the peer then completes the stream with
RESET_STREAM (its mandatory reply to STOP_SENDING) or a late FIN, the only
collection paths are (a) stream_recv() on a readable stream, (b) the send-side
ACK path, (c) stream_send()/stream_capacity() on a stopped send side. A
peer-initiated unidirectional stream has no send side and is never readable
again, so none applies: the stream stays in the map until the connection
closes and its MAX_STREAMS credit is never returned (collect() is what
increments local_max_streams_uni_next). Every refused or abandoned object
stream therefore permanently consumed one of the peer's stream slots. The Java
V2 server refuses inputs with shutdownInput (STOP_SENDING) at header, idle and
lifetime deadlines and on replay, so a peer that exhausted dataStreams with
refused inputs could never open another one.

Bidirectional streams were not leaked in the common case because the local
send side's FIN acknowledgment collects them, but the same leak applies when
the send side completed before the peer's reset arrived.

Fix (quiche/src/lib.rs, new Connection::collect_drained_stream)
----------------------------------------------------------------
After processing a received RESET_STREAM, after a STREAM frame written into a
draining receive buffer, and at the end of stream_shutdown(Read), collect the
stream when its receive side is draining, the stream is complete, it is not
readable, and its send side is not a stopped side still owing StreamStopped to
the application (the same rule the ACK-driven path uses). Bidirectional streams
still wait for their own send side. No change to any other collection path,
frame emission, or flow-control accounting.

Netty change (codec-classes-quic QuicheQuicStreamChannel.removeStreamFromParent)
--------------------------------------------------------------------------------
A closed stream channel whose input was shut down locally is released from the
parent's stream map (previously only after a received FIN). A drained native
stream never becomes readable again, so the map entry could never be used; the
native stream itself is collected by the quiche change above. New test
codec-native-quic QuicStreamCreditTest.refusedPeerUnidirectionalStreamReturnsItsStreamCredit:
a server with initial_max_streams_uni = 1 refuses three successive peer
unidirectional streams with shutdownInput(42) + close(); after each refusal the
client's peerAllowedStreams(UNIDIRECTIONAL) returns to 1 without any further
read. This test fails on the .3 native library (credit never returns) and is
run by the bundle build.

Version bump: 4.2.17.Final-pipestream.3 -> 4.2.17.Final-pipestream.4 in both
codec-classes-quic and codec-native-quic POMs; the library name
netty_quiche42_pipestream is unchanged.
