Implemented scope
  InputStore/OutputStore share one cooperative store lock, handle pool and
  admission-funded byte/name allowance. Output installation does not add another
  quota or refund unused promises. The policy advances from private format 3 to
  4 with outputs/output-pending namespaces; older private roots are refused, not
  converted. Authority database format 5 and the protocol wire grammar do not
  change. No dependency, native, Rust or upstream checkout is changed.

  A writer validates declared length, object ceiling, aggregate bytes and count
  before creating its bounded staging file. It hashes incrementally, verifies
  exact completed bytes, forces the file, links a non-overwriting installed name,
  synchronizes that directory, then removes and synchronizes staging. Its private
  identity binds store/authority installations, protocol context, complete input,
  producing attempt, local lease number and output index. Renewable lease expiry
  is an observation, not a physical object identity.

  Writers and readers share the input handle ceiling. A still-open descriptor
  prevents release of its handle; installed files and the original funding stay
  charged after close. A bounded namespace-dirty flag makes subsequent slot use
  and exact-set publication re-establish pending-directory synchronization after
  failed cleanup. Recovery synchronizes that namespace even when visibly empty.
  It validates all headers, identities, funding and aggregate geometry before
  hashing any installed output body, and validates all bodies before removing
  abandoned output staging. It never deletes an installed output on inference.

  SessionStore.succeedExecution holds the paired-store monitor through its writer
  transaction. It requires the exact finished output set, not an installed prefix
  or a set with live writers, and independently checks every descriptor and byte
  budget. Locators come from validated deployment endpoint configuration. One
  funded WORK/JOB image pair commits SUCCEEDED, the exact result manifest and the
  settled job together. Result-enabled success includes an empty manifest for
  zero outputs; durable-only success has no manifest or output availability.

  Current owner/application permission, original deadline, attempt/local lease and
  ancestor exclusion fences are checked again after metadata writes. A final UTC
  sample overtaking the proposed receipt OR output interval refuses CLOCK_UNSAFE
  with rollback. A branch requires verified prior STRICT child success and
  completed authority expansion. Paired recovery checks published files against
  their manifest instead of rerunning work to replace missing evidence.

  Existing installed slots cannot be silently reused by another lease. Safe
  metadata-authorized orphan reclamation and callback resource lifecycle remain
  required. The Java listener still advertises Core only. This increment is not
  a callback runtime, explicit retry, producer-1 expansion, closure writer,
  cancellation/revocation reconciliation, result-read lease/transport adapter,
  retirement or full cross-language V2 conformance. The protocol-neutral failure
  driver and external workload/equivalent authenticated durable streaming-gRPC
  baseline remain original goal deliverables. This checkpoint is not completion.
