Contract and implementation
  SessionStore.retry implements the existing Section 12.6 WORK retry contract
  as an owner-authorized local authority API. Current access and application
  gates must authorize retry. It accepts an exact expected attempt for any
  eligible admitted nonterminal work; no AWAITING_RETRY-only restriction is added.
  Existing fences, terminal outcomes, original deadline and physical/operation
  capacity retain their named refusals.

  One SQLite writer transaction replenishes WORK/JOB rewrite credits, advances
  the wire attempt once, clears the prior local lease expiry and commits the
  immutable receipt/accounting. Input, output funding, admission time, original
  deadline, child scope and completed expansion remain intact. The local lease
  counter is not reset; a replacement claim advances it. Mode 1 and completed
  mode 2 remain WAITING_CHILDREN. Retry does not run an application or delete
  old output bytes; existing replacement-claim cleanup rules remain in force.

  Final current authorization precedes the final clock/deadline check. Refusal
  rolls back all tentative writes, restored credits and the clock watermark.
  Exact operation replay remains authenticated evidence with no clock sampling,
  new attempt or extended promise, even after deadline/terminal settlement.
  Caller retry of producer-one work uses the independent producer-zero operation
  namespace, not the child's admission-operation namespace.

  Private Java database format 6 adds bounded typed retry intent plus indexed
  target/expected-attempt fields to the existing operation journal. Unique
  per-work expected-attempt keys and count/high-water checking require a complete
  sequence from admission attempt one to the current attempt. Each index is
  compared with its checksummed typed intent/receipt and admitted work/time.
  Earlier private layouts are refused without conversion. Wire schemas,
  commitments, negotiation profiles and input policy format are unchanged.

Reviewed regression scope
  RetryStoreTest covers active and AWAITING_RETRY replacement, original receipt
  replay/reopen, stale lease refusal, terminal/deadline fresh refusal, both branch
  modes and real producer-one input admission followed by caller retry. The
  caller retry deliberately reuses the child's admission operation identifier
  in its separate namespace; the original admission still replays.

  A replacement lease commits actual durable-only success with zero output
  objects; the old lease cannot publish. This is not alternate-attempt payload
  delivery or result-stream evidence. Two distinct concurrent operations with
  expected attempt one yield one attempt-two receipt and one CONFLICT. Both
  threads enter through real SessionStore handles, not an in-memory oracle.

  RetryStoreFailureTest compares exact work/job values, primitive fixed-record
  geometry and durable clock value/revision across final authorization, deadline,
  clock-regression and operation-capacity refusal. It requires the proposed
  receipt to remain absent. Recovery rejects a removed receipt even when the
  operation count is changed to conceal removal, and rejects an indexed expected
  attempt that contradicts its typed request. A legal multi-retry chain reopens.

  Static review corrected two test oracles before execution: non-expanding work
  retains expansionComplete=true, and fixed-record byte-array identities cannot
  serve as value-equality rollback assertions. Concurrent test cleanup releases
  its start latch even if readiness fails. No production exemption was added.
