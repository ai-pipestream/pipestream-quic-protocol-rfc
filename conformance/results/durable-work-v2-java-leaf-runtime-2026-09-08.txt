Implemented scope
  ExecutionRuntime invokes exact registered leaf application code after a durable
  worker claim and outside metadata transactions. The callback streams actual
  admitted input and funded output through a thread-confined context. Success uses
  the exact immutable publication transaction, not a fabricated result descriptor.
  Registered contract, mode and restart-safety policy must match admission. Unknown
  and branch callbacks are refused rather than silently converted.

  One host-owned runner enforces bounded physical callbacks globally and per owner,
  with no waiting queue. Before invocation it obtains an input reader and reserves
  a dedicated output-writer handle for nonzero output budgets. Sequential output
  writers borrow that credit without another handle charge. Readers cannot spend
  that reservation. Setup capacity refusal invokes no callback and does not turn
  transient dispatch pressure into a terminal computation failure.

  Every callback I/O operation checks current owner/application permission, attempt,
  durable local lease, ancestor exclusion and original execution deadline. The
  check and physical operation share the input monitor with replacement claims.
  Arbitrary callback code runs outside the monitor and must cooperate; there is no
  promise of forced preemption or exactly-once external effects. Captured contexts
  cannot issue I/O from another thread or after invocation.

  The process monotonic interval is checked around policy/clock callbacks and in
  committing authorization gates. Renewal adds process time only when the durable
  expiry actually advances; a frozen trusted UTC value cannot repeatedly restart
  the local interval. Current checks remain independent of the presenting TLS
  credential lifetime. Callback errors are frozen before choosing the outcome.

  Swallowed output-budget and interface errors prevent success. A requested success
  with unfinished output is FAILED/INTEGRITY_ERROR. Explicit retryable or failed
  outcomes may leave unpublished partial staging without having their disposition
  silently changed. Persistence failures or lost authority do not fabricate a new
  computation outcome. Generic application exceptions do not disclose their text.

  A newly committed CURRENT EXECUTING claim provides the durable deletion-eligibility
  evidence for strictly older (attempt, local lease) orphan output slots. The
  trusted low-level reclaim API does not itself confer that authority. All target
  identities, funding geometry and installed digests are validated before unlink.
  Same/future/foreign identities are preserved and refused. Per-funding physical
  readers, writers and reserved writer credits block reclamation. Unrelated funded
  objects are not blocked by those pins. Both namespaces are synchronized before
  reuse; no byte/name allowance is refunded and no published output is inferred
  reclaimable from absence. Terminal success cannot receive a replacement claim.
  Reclaim scans the two shared namespaces, retaining at most 512 target descriptors
  and hashing at most that job's funded installed payload bytes. The resource
  fixture does not establish constant-time discovery or many-job throughput.

  Physical cleanup retries idempotent closes at most twice. Confirmed descriptor
  closure allows the invocation permit to return even when directory cleanup
  reported an error; a persistently uncertain descriptor stays conservatively
  charged. Dirty namespaces and original funding remain independently accounted.

  No storage-format, wire-grammar, dependency, native or Rust code changes. Java
  still advertises Core only. This runner is not the background durable-job
  discovery scheduler, a branch runtime, explicit retry implementation, result-read
  service or activated durable-profile endpoint. Full cancellation/revocation,
  closure writing, retention/reconciliation and cross-language failure-driver
  coverage remain required, as does the original external workload/equivalent
  authenticated durable streaming-gRPC comparison. The goal is not complete.
