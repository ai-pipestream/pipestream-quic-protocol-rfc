Implemented contract
  Sections 12.5, 12.6 and 12.9 require committed restartable jobs, current
  execution ownership, explicit wire retries, independent deadline settlement,
  safe time and preserved accounting. They do not standardize a scheduling
  algorithm. This increment supplies actual background leaf dispatch in the Java
  authority library without changing the wire grammar or storage format.

  scanExecutions reads a finite keyset sweep of committed jobs. Each snapshot
  examines at most 64 checked job/work pairs plus one continuation key using the
  existing (generation,scope,entity) primary key. The first snapshot fixes the
  inclusive endpoint. Jobs admitted behind a cursor and transiently refused jobs
  are rediscovered in the next sweep. No cursor grants execution or mutates the
  durable attempt, lease, clock, input, operation receipt or completion record.
  Retiring rows may be skipped only on retained explicit retirement intent, never
  because required live metadata is missing. This internal API is not a caller
  interface and must not be exposed as unauthenticated cross-owner observation.

  ExecutionScheduler owns one dispatcher and a fixed daemon worker pool bounded
  by the shared runtime's global/per-owner geometry (at most 128 workers). Its
  handoff queue has zero waiting capacity. One bounded page, a sweep cursor,
  bounded in-flight and owner maps, saturating counters and one fixed diagnostic
  observation are retained. A physical dispatch race/refusal leaves the durable
  job discoverable; no volatile queue entry is the admission promise.

  Worker threads resolve retained-owner execution grants, not originating TLS
  credentials, and call the real ExecutionRuntime. The scan's observations are
  advisory: current transactional claim/publication checks remain authoritative.
  Live leases are not replaced merely because the process reopened. Expired
  ownership can be replaced without incrementing the wire attempt. Terminal
  jobs and AWAITING_RETRY are never automatically rerun. Unsupported branches
  receive a local APPLICATION_UNSUPPORTED diagnostic, not a fallback execution.

  Deadline maintenance uses the existing funded owner-independent transaction
  on the dispatcher, separately from saturated callback workers. Current safe
  UTC, durable watermark and cancellation precedence are checked at settlement.
  Physical callbacks and their handles remain charged until actual closure.
  Unsafe time or storage errors never manufacture success or erase a job.

  close stops new dispatch without interrupting callbacks, cancelling logical
  work or closing storage. An in-progress maintenance transaction can finish.
  awaitStopped uses one monotonic bounded wait for dispatcher and physical pool;
  false does not authorize the host to close stores or claim completion.

Resource and completion boundaries
  Discovery retains bounded records, not payloads or whole-session membership.
  Sweep cost still grows with all retained jobs, including terminal history, and
  includes per-job point reads and configured inter-page delays. Actual claim,
  settlement and publication retain their existing verification/storage costs.
  This does not demonstrate constant-time scheduling, indexed deadline lookup,
  many-job throughput, process peak RSS, power-loss resilience, or fairness
  beyond the explicit configured per-owner physical cap.

  No Java durable-profile listener is activated. Branch callbacks/producer-one
  ingress, explicit retry, closure writing, cancellation/revocation settlement,
  dependency/result read pins, retirement and endpoint/client integration remain
  required. Full cross-language V2 failure coverage and the external streaming
  workload versus equivalent authenticated durable gRPC are still required.
  Neither this checkpoint nor existing Core examples complete the full goal.

Review corrections before executing focused tests
  Tests now use each owner's actual returned generation, not generation1 for
  every principal. Declaration IDs are increasing even when admissions occur
  in a different order. A mode 1 job is WAITING_CHILDREN, while an executing
  leaf's wire state remains ACTIVE. Tests distinguish protocol enum names from
  internal job stages and use the actual on-disk Java Binding return type.
  A marker admitted after a terminal UTC 1100 commit uses UTC 1100, not 1000.
  Process completion counters are checked after physical shutdown, not during
  the small interval between authoritative publication and runtime cleanup.
  Independent owners' terminal outcomes are awaited independently. Bounded
  polling yields between metadata reads, and cleanup asserts physical stop
  before closing paired stores. These are fixture corrections, not claims of
  failing production regression tests.
