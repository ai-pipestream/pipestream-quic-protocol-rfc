Scope
-----
The Java package-private StreamTransport is a connection-confined owner for one
typed bidirectional control stream and explicitly bounded unidirectional data
stream leases. It installs separate native ordinary/reserved send allowances,
fixed receive-window geometry, per-direction concurrent slots, a finite lifetime
stream-ordinal ceiling, one bounded in-flight data chunk, explicit FIN/reset and
explicit slot release. It is transport machinery, not profile negotiation,
authorization, object integrity, receipt correlation or durable settlement.

Five focused StreamTransportTest fixtures were added:
  limitsValidateGeometryAndNativeReservation
  stalledDataDoesNotBlockTypedControlAndFinFollowsExactPayload
  serverToClientDataUsesIndependentControlAndExplicitSettlement
  localResetSettlesQueuedWriteBeforeExplicitSlotRelease
  stalledWriteDeadlineDoesNotPreventControlProgress

The loopback fixture uses real mutual TLS and QUIC. It negotiates only Core
capabilities and does not advertise or simulate a durable profile. The two data
directions independently stall a unidirectional stream at the configured receive
window while typed control frames continue in both directions. Resume requires
the exact payload and a received FIN frame. Local reset settles queued owner
resources without claiming peer receipt. Slot release remains explicit.

Late empty FIN: reproduced RED
--------------------------------
The retained Java server QLOG showed server stream payload acknowledged before a
late empty FIN was accepted. A peer FIN then reached the application, after which
the server emitted ACK plus MAX_STREAMS but no STREAM FIN. Native local FIN
acceptance was therefore not treated as peer delivery.

Native FIN acknowledgment fix and edge coverage
-------------------------------------------------
The fix tracks a written FIN independently from payload offset ranges. Stream
completion requires both complete payload acknowledgment and acknowledgment of
the FIN at the correct final offset. Reset abandons that FIN wait because reset
reliability is tracked separately by packet recovery.

Six focused SendBuf unit edges are present and green in the final native run:
  late_empty_fin_after_payload_ack_waits_for_fin_ack
    Payload ACK before a late empty FIN does not complete; emission alone does
    not complete; the matching FIN ACK completes it.
  wrong_final_offset_does_not_ack_fin
    FIN ACKs at lower or higher offsets do not complete the stream.
  repeated_fin_after_ack_does_not_rearm
    Repeating an already acknowledged empty FIN does not recreate a pending FIN.
  fin_ack_before_payload_gaps_close_waits_for_data
    A correct FIN ACK cannot bypass an outstanding payload ACK gap.
  wholly_empty_fin_waits_for_fin_ack
    Offset-zero payload bookkeeping plus the offset-zero FIN ACK are both used.
  reset_abandons_fin_wait
    Reset clears the pending FIN requirement and completes the reset send side.

The packet-driven late-empty-FIN regression is also green in the final run.

Remaining gates and limitations
-------------------------------
- This milestone does not prove a full Java durable-work/result endpoint, durable
  request settlement, receipt/object retention, or Java-to-Rust durable-profile
  interoperability.
- Native retained stream offsets are admission accounting, not exact heap/RSS.
  Java queues, TLS, datagrams, QUIC metadata and partial backing buffers remain
  separately bounded concerns.
- Configured receive/send geometry is a local transport policy. It does not
  guarantee peer credit delivery, congestion capacity, network delivery, or all
  end-to-end durable admission gates under arbitrary packet loss.
- The diagnostic QLOG is evidence for this reproduced interleaving, not a wire
  conformance oracle or a general packet-loss proof.
