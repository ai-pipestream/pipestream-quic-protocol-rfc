Scope
  The blocking client Journal now retains bounded scope identity/member records
  and verified coverage summaries. observe_scope_page takes the actual request
  and authenticated/correlated response, accepts out-of-order/overlapping pages
  and compatible older unsealed snapshots, and checks interval omissions and
  count constraints. Only full membership matching the recomputed immutable seal
  sets membership_verified. Empty pages and state hints cannot fabricate missing
  identities, full WORK views, attempts, manifests or status coverage.

  Known declaration receipts, parent-scope producer/membership, immutable branch
  allocation, work/manifest terminal evidence and ancestor cancellation fences
  constrain new evidence in either arrival order. Valid child-first metadata can
  survive reopen as a pending relationship without inventing parent admission.
  Later parent pages AND sealing receipts revalidate earlier child relationships
  in the same transaction. Contradictions refuse and preserve prior evidence.

  record_checkpoint uses a conservative complete-local-evidence policy: verified
  full membership, every terminal WORK view and already saved verified child
  coverage. It incrementally recomputes counters and the exact status root and
  validates closure times and STRICT parent success. A failed parent may terminate
  before child closure, but enclosing scope coverage still waits for that child.
  root_completion constructs the exact retained root DRAIN request; it does not
  assert the transport has drained or the authority has acknowledged shutdown.

  This full-evidence policy costs extra member reads and local storage; it is
  not a new universal wire requirement to fetch every WORK view. Scans and receipt
  comparisons remain blocking. Scope seals/status roots are incremental and reopen
  checks children before parents without recursion or a whole-tree buffer. These
  structural properties do not establish measured latency, heap, native-memory,
  RSS or workload throughput bounds.

  The observation ceiling now applies independently to work views, manifests,
  selections, scope identities, member rows and coverage. Defaults remain 4096
  entries per inventory and 4096 operations, configurable from 1 to 1,000,000.
  There is no implicit eviction. Existing guarded SQLite limits separately cap
  DB/WAL/rollback-journal/shared-memory file lengths. The local client format is
  3; older formats refuse before WAL configuration without conversion, deletion
  or replacing unresolved history. Authority storage and dependencies are unchanged.

  Section 12 explicitly states the both-arrival-orders consistency requirement,
  bounded pending relationship evidence and INTEGRITY_ERROR for contradictions.
  Parent-first delivery is not required. Wire/CDDL/frozen byte layouts did not change.

  The positive nested case includes child-first metadata, exclusive reopen before
  observing the parent and eventual full root coverage without fabricated parent
  fields. Negative tests independently change parent producer, sealed membership,
  child scope, child producer and parent work identity in both arrival orders.
  Another test merges 300 members from tail-first, overlapping and stale pages
  across reopen without replacing terminal hints or pretending they are WORK views.
  Injected SQLite write faults prove atomic rollback. A forced process exit waits
  for a flushed post-commit marker, kills the child, observes unsuccessful exit
  and reopens exact membership/root coverage while retaining the unresolved intent.
